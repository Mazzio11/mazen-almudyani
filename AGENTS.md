# Project conventions

Use English for source code, identifiers, comments and technical documentation. Communicate with the user in Arabic. Arabic website translations and requested Arabic handover guides are intentional exceptions.

Keep exactly three featured projects. Treat project screenshots as evidence of visible UI only, not proof of backend functionality. Never invent certifications, stacks, test results or metrics. Contact email was approved in this conversation. Do not publish without final public-content review and an identified destination.

Run typecheck, lint and production build after code changes. Keep content in src/content.ts. Respect reduced motion, keyboard navigation and RTL. Use relative assets and hash routes for GitHub Pages subdirectories.
